USB Serial Communication Protocol Specification for BeeDrive 5.0.1

BeeDrive 5.0.1 USB 串口通信协议规范

This document outlines the byte-level interface rules required to communicate with the motor controller hardware over a USB serial connection. Once the device is plugged in, it should appear as a serial peripheral. The Baudrate is 115200.

本文档概述了通过 USB 串口连接与电机控制器硬件进行通信所需的字节级接口规则。设备插入后，应显示为串口外设。波特率为 115200。

1. Frame Architecture

All inbound and outbound packets follow a strict framing pattern. Multibyte numeric values (such as 16-bit integers and 32-bit floats) use Little-Endian format (least significant byte first).

Byte Index Field Name Data Type Value / Description
0 Start Byte uint8 Always 0x02
1 Command ID uint8 Identifies the packet payload rule (see Registry)
2 to N-3 Payload Variable Data parameters belonging to the specific Command ID
N-2 Checksum uint8 8-bit XOR validation check
N-1 End Byte uint8 Always 0x03

Checksum Logic

The checksum is compiled by running an XOR (^) calculation across all sequential bytes starting immediately after the Start Byte up to, but excluding, the Checksum byte itself.

2. Outbound Frame Profiles (Control panel → Device)

Ensure byte arrays exactly match the targeted sizes. Out-of-bounds parameters will automatically be clamped internally by the motor firmware.

2.1 Base Resistance (Command ID: 0x00)

Total Frame Size: 9 Bytes
  • Bytes 2–3: int16 | Concentric Force limit (in decinewtons, 0.1N). Must be ≥ 0 & ≤ 8000.
  • Bytes 2–3: int16 | 向心力限制（单位：角牛顿，0.1N）。必须 ≥ 0 且 ≤ 8000。
  • Bytes 4–5: int16 | Eccentric Force limit (in decinewtons, 0.1N). Must be ≥ 0 & ≤ 8000.
  • Bytes 4–5: int16 | 离心力限制（单位：角牛顿，0.1N）。必须 ≥ 0 且 ≤ 8000。
  • Byte 6: uint8 | SSR Flag. Set to 0xFF for True, 0x00 for False.
  • Byte 6: uint8 | SSR 标志。0xFF 表示开启，0x00 表示关闭。

2.2 Spring Simulation (Command ID: 0x01)

Total Frame Size: 8 Bytes
  • Bytes 2–3: int16 | Target extension spring path length (in mm). Must be ≥ 0. If the length is too small, the feeling will be very bad.
  • Bytes 2–3: int16 | 目标弹簧拉伸行程长度（单位：mm）。必须 ≥ 0。如果长度设定太小，力感体验会非常差。
  • Bytes 4–5: int16 | Max peak force generated at full extension (in 0.1N). Must be ≥ 0 & ≤ 8000.
  • Bytes 4–5: int16 | 完全拉伸时产生的最大峰值力（单位：0.1N）。必须 ≥ 0 且 ≤ 8000。

2.3 Progressive Resistance Band (Command ID: 0x14)

Total Frame Size: 11 Bytes
  • Bytes 2–3: int16 | Slack / Rest physical length of the band (in mm). Must be ≥ 0.
  • Bytes 2–3: int16 | 阻力带的初始松弛/静止物理长度（单位：mm）。必须 ≥ 0。
  • Bytes 4–5: int16 | Maximum safe extension length boundary (in mm). Must be ≥ Rest length.
  • Bytes 4–5: int16 | 最大安全拉伸长度边界（单位：mm）。必须 ≥ 静止长度。
  • Bytes 6–7: int16 | Max structural peak force at full extension (in 0.1N). Must be ≥ 0 & ≤ 8000.
  • Bytes 6–7: int16 | 完全拉伸时的最大结构峰值力（单位：0.1N）。必须 ≥ 0 且 ≤ 8000。
  • Byte 8: uint8 | Curve non-linearity factor coefficient. Valid values: 0 to 4.
  • Byte 8: uint8 | 曲线非线性系数。有效取值范围：0 到 4。

2.4 Isokinetic Limit (Command ID: 0x11)

Total Frame Size: 8 Bytes
  • Bytes 2–3: int16 | Velocity target (in mm/s). Must be ≥ 0. The force will start increasing after this speed, following a slope defined by the parameter "Slope".
  • Bytes 2–3: int16 | 目标速度（单位：mm/s）。必须 ≥ 0。超过此速度后阻力将开始增加，增加规律遵循由“Slope”参数定义的斜率。
  • Bytes 4–5: int16 | Slope parameter (in 0.1N/(m/s)). Must be ≥ 0 & ≤ 4000.
  • Bytes 4–5: int16 | 斜率参数（单位：0.1N/(m/s)）。必须 ≥ 0 且 ≤ 4000。

2.5 Vibrations (Command ID: 0x04)

Total Frame Size: 8 Bytes
  • Bytes 2–3: int16 | Vibration force amplitude factor (in 0.1N).
  • Bytes 2–3: int16 | 震动力幅值参数（单位：0.1N）。
  • Bytes 4–5: int16 | Targeted mechanical cycling frequency (in Hz).
  • Bytes 4–5: int16 | 目标机械循环频率（单位：Hz）。

2.6 System Breakout Inertia (Command ID: 0x15)

Total Frame Size: 6 Bytes
  • Bytes 2–3: int16 | Starting static breakthrough force resistance limit (in 0.1N). Must be ≥ 0 & ≤ 8000.
  • Bytes 2–3: int16 | 初始静态突破力阻力限制（单位：0.1N）。必须 ≥ 0 且 ≤ 8000。

2.7 Telemetry Stream Request (Command ID: 0x0E)

Total Frame Size: 4 Bytes

Polling payload to command an immediate backplane telemetry message refresh.

Fixed Byte Array String: [0x02, 0x0E, 0x0E, 0x03]

3. Inbound Telemetry Packet (Device → Android)

Upon verifying a polling request, the device returns a fixed 25-byte binary status frame mapping the internal sensor matrices.

Byte Index Field Name Data Type Unit / Interpretation Description
0 Start Byte uint8 0x02
1 Command ID uint8 0x0E (Validation matching)
2 System State uint8 Current structural active state machine index status
3–6 Real Position int32 Current linear rope/draw coordinate extension (in mm)
7–8 Current Speed int16 Real-time travel velocity metrics (in mm/s)
9–10 Total Force int16 Instantaneous compound force calculations (in 0.1N)
11–12 FET Temperature int16 Power semiconductor power-stage switch array thermals
13–14 Motor Temperature int16 Internal core motor winding inductive thermal sensor
15–16 Brake Temperature int16 Dynamic braking chopper power resistor thermal sensor
17–18 Bus Voltage int16 DC Main power rail input distribution line voltage
19 Checksum uint8 Inbound response packet validator token
20 End Byte uint8 0x03
